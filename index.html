Справочник по обходу блокировок

Как работают zapret, VPN и прокси — и почему они конфликтуют

1Как работает zapret

zapret — утилита обхода DPI-блокировок на уровне сетевого стека Windows. Она не шифрует трафик и не меняет IP — она делает так, чтобы провайдер не распознал, что вы обращаетесь к запрещённому ресурсу.

Принцип работы

  1. Устанавливает драйвер-перехватчик на уровне ядра системы.
  2. Перехватывает исходящие пакеты на физическом сетевом адаптере.
  3. Модифицирует пакет по заданной стратегии:
    • фрагментирует — рвёт TLS-рукопожатие на части;
    • добавляет фейковые пакеты — сбивает DPI с толку;
    • меняет порядок — обходит сигнатурные фильтры.
  4. Модифицированный пакет уходит дальше — сервер собирает его как обычный.
💡 Что важно понимать
  • Работает только с трафиком, который идёт напрямую через физический адаптер.
  • Ничего не знает про VPN-туннели, прокси и виртуальные адаптеры.
  • Управляется правилами в текстовых списках: домены, IP, порты.

Из чего состоит

КомпонентЗадача
winws.exeГлавный процесс — перехват и модификация пакетов
Драйвер перехватаРаботает на уровне ядра, видит весь трафик
*.bat файлыСтратегии обхода — наборы аргументов для winws.exe
lists/Списки доменов, IP и исключений

2VPN и почему режим TUN ломает zapret

Что такое TUN

TUN — сокращение от tunnel (туннель). Это виртуальный сетевой интерфейс, который создаёт VPN-клиент. Для системы он выглядит как обычная сетевая карта, но физически её не существует.

Что делает VPN при включении TUN

Создаёт виртуальный адаптер
→
Меняет таблицу маршрутизации
→
Весь трафик идёт в туннель
→
Шифрует → отправляет на сервер
  1. Создаётся виртуальный адаптер с собственным IP-адресом.
  2. Изменяется системная таблица маршрутизации — весь трафик по умолчанию идёт в этот виртуальный адаптер.
  3. VPN-клиент перехватывает пакеты из адаптера, шифрует их и отправляет через физический адаптер на удалённый сервер.

Конфликт с zapret

ШагЧто происходит
1Приложение отправляет пакет в интернет.
2Система по маршрутам отправляет его в виртуальный адаптер VPN.
3zapret перехватывает пакет на физическом адаптере, когда VPN уже его зашифровал.
4zapret пытается «улучшить» шифрованный пакет — ломает его.
5Соединение рвётся. Discord/YouTube падают.
🚫 Итог
Одновременно TUN и zapret работать не могут. Либо одно, либо другое.

Почему правила «только для выбранных приложений» не спасают

  • Они применяются внутри VPN-клиента — то есть после того, как трафик уже ушёл в виртуальный адаптер.
  • До zapret этот трафик доходит уже в виде зашифрованного VPN-потока.
  • zapret не может определить, к какому ресурсу идёт соединение.

3Системный прокси при выключенном TUN

Системный прокси — настройка Windows, которая говорит приложениям: «отправляй HTTP/HTTPS через вот такой адрес». Хранится в реестре в разделе Internet Settings пользователя.

Ключевые параметры

ПараметрЧто означает
ProxyEnableВключён (1) или выключен (0)
ProxyServerАдрес и порт прокси
AutoConfigURLСсылка на PAC-файл (если используется)

Кто читает системный прокси

ПрограммаЧитает?
Браузеры (Chrome, Edge, Firefox)✅ Да
curl, git, pip, npm✅ Да
node.exe (встроенный fetch)❌ Нет
Discord, Telegram, Electron-приложения❌ Нет
Игры, торрент-клиенты❌ Нет
✅ Плюсы режима
  • VPN не создаёт виртуальный адаптер → конфликта с zapret нет.
  • Программы, которые не читают прокси, идут напрямую → обрабатываются zapret.
  • Программы, которые читают прокси, идут через VPN.
⚠️ Минусы режима
  • Если VPN-клиент аварийно завершится — параметры прокси останутся в реестре. Windows будет отправлять трафик «в никуда» — интернет «зависнет».
  • Не все программы уважают системный прокси.

Как лечить застревание

Сбросить ProxyEnable в 0 и удалить ProxyServer из реестра (команды — в разделе 6).

4Как направить конкретные приложения через прокси

Три уровня настройки

УровеньКто уважаетДля чего подходит
Системный прокси Браузеры, curl, git, npm Основной способ
Переменные окружения node.exe, curl, git, pip Точечно для консольных программ
TUN Все, включая игры и Discord Только если конфликт с zapret неважен

Схема выбора

Нужно направить Chrome?
→
Системный прокси
Нужно направить Codex?
→
Системный прокси + env-переменные
Нужно направить Discord/игру?
→
Только TUN (конфликт с zapret неизбежен)

Почему нельзя «просто поставить галочку»

Каждая программа сама решает, читать ли системные настройки. Многие современные приложения (на Go, Rust, Electron) их игнорируют. Именно поэтому для таких программ единственный способ — TUN, который перехватывает всё подряд.

💡 Специфика Node.js
Встроенный fetch в Node.js не читает HTTP_PROXY/HTTPS_PROXY по умолчанию. Чтобы заставить его использовать прокси, нужна переменная NODE_USE_ENV_PROXY=1 (Node.js 20.6+) либо явное указание прокси в конфиге приложения.

5Матрица совместимости

Комбинация zapret VPN для Codex Discord / YouTube Стабильность
Только zapret ✅ ❌ ✅ ✅
Только VPN (TUN) ❌ ✅ ❌ ⚠️
zapret + VPN (TUN) ❌ ✅ ❌ ❌
zapret + VPN (системный прокси, без TUN) ✅ ✅ ✅ ⚠️
zapret + VPN (системный прокси + env для конкретных программ) ✅ ✅ ✅ ✅
🏆 Рекомендуемая схема
  • zapret работает всегда — Discord, YouTube, всё остальное.
  • VPN включён в режиме без TUN (только локальный прокси-порт).
  • Программы, которым нужен VPN, направляются на этот порт через системный прокси или переменные окружения.
  • Программы, которые не читают прокси, работают напрямую → их обрабатывает zapret.

Диагностика

# Проверить, слушает ли порт прокси
Test-NetConnection 127.0.0.1 -Port <порт>

# Проверить, идёт ли трафик через прокси
curl.exe --proxy http://127.0.0.1:<порт> https://api.ipify.org

# Посмотреть активные процессы
Get-Process winws,Happ,xray,node -ErrorAction SilentlyContinue

# Показать таблицу маршрутизации (видно, есть ли TUN)
route print -4

# Проверить переменные прокси в текущей сессии
echo "HTTP_PROXY=$env:HTTP_PROXY"
echo "HTTPS_PROXY=$env:HTTPS_PROXY"

Сброс застрявшего системного прокси

# Отключить и удалить параметры прокси
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyEnable /t REG_DWORD /d 0 /f
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyServer /f
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v AutoConfigURL /f

Env-переменные для Node.js

# В отдельной сессии PowerShell
$env:NODE_USE_ENV_PROXY = "1"
$env:HTTP_PROXY         = "http://127.0.0.1:10809"
$env:HTTPS_PROXY        = "http://127.0.0.1:10809"
⚠️ Осторожно с setx
setx записывает переменные в систему, а не в текущую сессию. Если задать HTTP_PROXY через setx, а VPN-клиент потом выключить — многие программы начнут пытаться идти в мёртвый прокси. Для временных сессий используйте $env:.
